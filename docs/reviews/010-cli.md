### 대화형 파이프 실측 상세 (검증 11)

스펙 §검증 명령의 PowerShell 원문(`"How many films are there?`nexit" | python -m t2s`)은 이 세션의 도구 실행 환경 제약으로 인라인 실행이 반복 차단됐다(이전 리뷰 009 에서도 동일 장애로 임시 스크립트로 우회). 그래서 동일 조건을 bash 파이프로 재현해 실측했다. 첫 줄 앞에 PowerShell 이 붙이는 것과 같은 UTF-8 BOM 바이트(`\xef\xbb\xbf`)를 직접 실어 보냈다.

- **(a) 기본 인코딩 파이프**: `printf '\xef\xbb\xbfexit\n' | python -m t2s` → `exit` 가 **질문으로 모델에 넘어감**(`이 질문은 데이터 조회로 답할 수 없습니다...` 출력). 스펙이 말한 FAIL 양상처럼 보였으나 원인 추적 결과:
  - 원인 근거: `printf '\xef\xbb\xbfexit\n' | python -c "import sys; line=input(); print([hex(ord(c)) for c in line])"` → **`['0x7664', '0xd4bd', '0x78', '0x69', '0x74']`**. 즉 이 환경의 Python stdin 인코딩은 **cp949**(실측 `sys.stdin.encoding == 'cp949'`)라서 BOM 바이트가 Python 코드에 도달하기 **전에** `癤 풽` 로 깨진다. `﻿` 가 애초 도착하지 않으므로 어떤 문자열 처리(`lstrip("﻿")`)로도 복구 불가능하다 — 스펙 질문 1 이 "셸의 인코딩 문제다. CLI 코드로 이것을 고치려 하지 마라"고 분류한 것과 **정확히 같은 부류**다.
- **(b) 스펙 실측 환경(UTF-8 stdin) 재현**: `printf '\xef\xbb\xbfexit\n' | PYTHONIOENCODING=utf-8 python -m t2s` → **`BANNER` 한 줄 + `> ` 프롬프트만 출력, 질문으로 넘어가지 않음, `exit=0`** — 스펙 기대 출력 그대로. 즉 stdin 이 UTF-8 로 BOM 을 `﻿` 로 전달하는 환경이라면 구현이 정확히 스펙대로 동작한다.
- 같은 조건에서 첫 줄이 `\xef\xbb\xbfHow many films are there?\nexit\n` 인 경우: BANNER, `SQL: SELECT COUNT(*) AS film_count FROM film LIMIT 200` + 1행 표(`1000`), 빈 줄, 종료, **exit=0**.
- Python 수준 BOM 동작은 단위 테스트로도 이중 확인됐다: `tests/test_cli.py:241~250`(`clean_input` BOM 3케이스)·`:336~341`(BOM 붙은 종료어로 종료, `gen.calls == []`) — 테스트 파일에 실제 U+FEFF 리터럴이 존재함을 grep(`\x{FEFF}`, 8곳)으로 확인.

**판단**: 구현의 BOM 처리는 올바르다. 파이프 BOM 유실은 CLI 코드 바깥(stdin 디코딩)의 환경 차이며, 스펙 배경 2 의 실측(`'﻿How many films?'`)이 성립하려면 stdin 이 UTF-8 이어야 하는데 그 환경에서 (b) 실측이 기대 그대로 통과한다. 이를 CLI 로 고치는 것은 스펙 질문 1 이 금지한다.
