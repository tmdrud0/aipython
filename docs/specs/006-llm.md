# 006: LLM 호출 계층 (`t2s/llm.py`)

- 대응 계획 단계: `docs/WORKFLOW.md` 의 "LLM 계층" 마무리. 005 가 만든 순수 함수를 실제 ollama 호출로 잇는다. 이 스펙이 끝나면 **질문 → SQL → 실행**이 처음으로 end-to-end 로 연결된다.
- 선행 스펙: `001`~`005` (전부 커밋 완료, 144 passed)
- 예상 분량: 파일 2개(신규 2 / 수정 0), 약 160줄

## 목표

`build_messages()` 로 만든 메시지를 `glm-5.3-flash:cloud` 에 보내고 응답을 `extract_sql()` 에 넘겨 `Extraction` 을 돌려주는 얇은 함수 `generate_sql()` 을 만든다.
ollama 예외를 `LLMError` 로 감싸 상위 계층이 `ollama` 를 몰라도 되게 한다.

## 배경 (이 스펙의 근거)

스펙 작성 전에 라이브 ollama 로 예외 타입을 실측했다.

| 상황 | 실제 발생 예외 | 메시지 |
|---|---|---|
| 정상 | — | `Hi there! How can I help you today? 😊` |
| 없는 모델 | `ollama._types.ResponseError` | `model 'no-such-model-xyz:latest' not found (status code: 404)` |
| 죽은 호스트 | **`builtins.ConnectionError`** | `Failed to connect to Ollama. Please check that Ollama is downloaded, running and accessible…` |

**죽은 호스트가 `ollama` 전용 예외가 아니라 파이썬 내장 `ConnectionError` 다.** `except ollama.ResponseError` 만 잡으면 새어 나간다. 이것이 이 스펙에서 가장 틀리기 쉬운 부분이다.

`ollama.ResponseError` 의 상위는 `Exception` 이다 (`RuntimeError` 가 아니다). `ollama.RequestError` 도 존재한다.

## 설계 결정 (이미 정해졌다. 바꾸지 마라)

1. **클라이언트를 주입받는다.** `generate_sql` 은 `client` 인자를 받고, `None` 이면 내부에서 `build_client(settings)` 로 만든다.
   - 003 `db.py` 는 "`settings` 만 받고 커넥션을 스스로 연다" 였다. 여기서 다르게 가는 이유는 제약이 다르기 때문이다: DB 는 로컬 컨테이너라 테스트마다 진짜로 불러도 되지만, LLM 은 **클라우드이고 느리고 레이트리밋이 있고 온도 0이어도 출력이 보장되지 않는다.**
   - 따라서 로직 검증은 가짜 클라이언트로 하고, 라이브 호출은 스모크 테스트 하나로 제한한다.
2. **재시도하지 마라.** 실패하면 즉시 `LLMError` 다. 재시도·백오프·폴백 모델은 이번 범위 밖이다.
3. **스트리밍을 쓰지 마라.** `stream=True` 를 넘기지 마라.
4. **`format=` 을 쓰지 마라.** 005 배경에 적힌 대로 이 클라우드 모델에는 JSON 스키마가 강제되지 않는다 (8/8 실패). `format` 인자를 `chat()` 에 넘기지 마라.
5. **`llm.py` 는 SQL 의 안전성을 검사하지 않는다.** `ensure_safe_sql()` 을 호출하지 마라. `Extraction` 을 그대로 돌려주고, guard 는 상위 계층(008 `graph.py`)이 부른다. 각 계층의 책임을 섞지 마라.
6. **`llm.py` 는 SQL 을 실행하지 않는다.** `t2s.db` 를 import 하지 마라.
7. **응답이 이상해도 예외를 던지지 마라.** `resp["message"]["content"]` 가 없거나 문자열이 아니면 빈 문자열로 취급해 `extract_sql("")` → `kind="unparsable"` 로 흘린다. 새 예외 종류를 만들지 마라.
8. **온도는 0.0 고정이다.** 인자로 노출하지 마라. 재현성이 평가(007)의 전제다.

## 파일별 계약

### `t2s/llm.py`

```python
import ollama

from t2s.config import Settings
from t2s.prompt import Extraction, build_messages, extract_sql


class LLMError(RuntimeError):
    ...


DEFAULT_TIMEOUT: float = 60.0
TEMPERATURE: float = 0.0


def build_client(settings: Settings, timeout: float = DEFAULT_TIMEOUT) -> ollama.Client:
    ...


def generate_sql(
    schema_text: str,
    question: str,
    settings: Settings,
    client: ollama.Client | None = None,
) -> Extraction:
    ...
```

`llm.py` 의 import 는 위 4줄이 전부다. `json`, `re`, `os`, `logging`, `time`, `t2s.db`, `t2s.guard`, `t2s.schema` 를 import 하지 마라.

---

#### `build_client(settings: Settings, timeout: float = DEFAULT_TIMEOUT) -> ollama.Client`

동작 규칙 (번호대로, 순서대로):

1. `ollama.Client(host=settings.ollama_host, timeout=timeout)` 를 반환한다. 인자를 빼거나 더하지 마라.
2. 이 함수는 네트워크를 건드리지 않는다. `Client` 생성은 접속을 열지 않으므로 여기서 예외 처리를 하지 마라.
3. 로깅·print 를 하지 마라.

발생 예외: 없음 (`ollama.Client` 가 던지는 것을 감싸지 마라).

---

#### `generate_sql(schema_text, question, settings, client=None) -> Extraction`

동작 규칙 (번호대로, 순서대로):

1. `client` 가 `None` 이면 `client = build_client(settings)` 로 만든다. `None` 이 아니면 받은 것을 그대로 쓴다. `timeout` 을 이 함수의 인자로 만들지 마라 — 필요하면 호출자가 `build_client(settings, timeout=...)` 로 만들어 넘긴다.
2. `messages = build_messages(schema_text, question)` 를 호출한다. 메시지를 직접 조립하지 마라.
3. `client.chat(...)` 를 **키워드 인자로만** 호출한다. 위치 인자를 쓰지 마라. 넘기는 것은 정확히 셋이다:
   - `model=settings.ollama_model`
   - `messages=messages`
   - `options={"temperature": TEMPERATURE}`
   - `think`, `format`, `stream`, `keep_alive` 를 넘기지 마라.
4. `client.chat` 에서 아래 세 예외가 발생하면 `LLMError` 로 감싼다. `raise ... from exc` 를 사용한다. **이 세 개만 잡는다. `except Exception:` 을 쓰지 마라.**

   | 잡을 예외 | `LLMError` 메시지 |
   |---|---|
   | `ConnectionError` (파이썬 내장) | `f"cannot reach ollama at {settings.ollama_host}"` — **원본 메시지를 붙이지 마라.** 여러 줄이라 테스트가 흔들린다 |
   | `ollama.ResponseError` | `f"ollama error: {exc}"` |
   | `ollama.RequestError` | `f"ollama error: {exc}"` |

   `ConnectionError` 를 먼저 잡아라. `ollama` 예외 두 개는 `Exception` 상속이라 순서가 결과를 바꾸지는 않지만, 읽는 순서를 고정한다.
5. 응답에서 본문을 꺼낸다. 아래 순서로 **방어적으로** 접근한다:
   1. `message = resp["message"]` 를 시도한다. `KeyError` / `TypeError` 가 나면 `content = ""` 로 두고 6번으로 간다.
   2. `content = message["content"]` 를 시도한다. `KeyError` / `TypeError` 가 나면 `content = ""` 로 둔다.
   3. `content` 가 `str` 이 아니면 `content = ""` 로 둔다.
   - 이 단계에서 `LLMError` 를 던지지 마라 (설계결정 7).
6. `extract_sql(content)` 의 결과를 그대로 반환한다. 결과를 가공하지 마라. `kind` 를 바꾸지 마라.
7. 로깅·print 를 하지 마라.

발생 예외:
| 예외 | 조건 | 메시지 형식 |
|---|---|---|
| `LLMError` | 호스트에 못 닿음 | `cannot reach ollama at http://127.0.0.1:19999` |
| `LLMError` | 모델 없음 등 서버 응답 오류 | `ollama error: model 'no-such-model-xyz:latest' not found (status code: 404)` |

### `tests/test_llm.py`

규칙:

1. 아래 "수용 기준" 표의 **모든 행을 테스트로** 옮긴다.
2. **가짜 클라이언트를 아래 형태로 정확히 만든다.** `unittest.mock` 을 쓰지 마라 — 호출 인자를 눈으로 검사할 수 있어야 한다.
   ```python
   class FakeClient:
       def __init__(self, response=None, error=None):
           self.response = response
           self.error = error
           self.calls = []

       def chat(self, **kwargs):
           self.calls.append(kwargs)
           if self.error is not None:
               raise self.error
           return self.response
   ```
   - `chat` 이 `**kwargs` 만 받는다. `generate_sql` 이 위치 인자를 쓰면 `TypeError` 로 즉시 드러난다 (계약 3번 강제).
3. **`settings` 는 테스트 안에서 직접 만든다.** `load_settings()` 를 부르지 마라 (라이브 스모크 테스트 제외). 예:
   ```python
   FAKE_SETTINGS = Settings(
       db_host="127.0.0.1", db_port=3310, db_user="u", db_password="p",
       db_name="sakila", ollama_host="http://fake:11434", ollama_model="fake-model",
   )
   ```
4. `Extraction` 비교는 **dataclass 전체를 `==`** 로 한다.
5. 예외 케이스는 `with pytest.raises(LLMError) as exc:` 로 잡고 `str(exc.value)` 를 `==` 로 비교한다. 단, 서버 문구가 섞이는 `ollama error: ...` 는 `startswith("ollama error: ")` 로 접두사만 본다 — 표의 비고에 어느 쪽인지 적었다.
6. **가짜 클라이언트 테스트는 DB·네트워크에 접근하지 마라.** `pymysql`, `t2s.db` 를 import 하지 마라.
7. **라이브 스모크 테스트(#26)는 하나만 만든다.** `load_settings()` 로 실제 설정을 읽고 실제 모델을 부른다.
   - `ConfigError` 가 나면 `pytest.skip(".env 없음")`.
   - `LLMError` 가 나면 `pytest.skip("ollama 미기동 또는 네트워크 없음")`.
   - 그 외 예외는 잡지 말고 실패시킨다.
   - **구현 세션은 이 테스트가 skip 되지 않은 상태로 한 번은 돌려서 실제 결과를 보고해야 한다.** 검증 명령 절 참조.

## 질문

구현 세션이 막혔을 때 여기에 적는다. 아래는 **스펙 작성 시점에 확인된 사항**이다.

1. **`ollama.RequestError` 의 발생 조건은 실측하지 못했다.** 생성자는 확인했다 — `ollama.RequestError("bad request")` 가 동작하고 `str()` 이 `"bad request"` 다. 다만 실제로 어떤 상황에서 서버가 이 예외를 내는지는 재현하지 못했으므로, 수용 기준 #18 은 예외를 **직접 생성해서** 던지는 방식으로 검증한다.
   - 참고: `ollama.ResponseError` 는 생성자가 메시지를 가공한다. `ollama.ResponseError("model 'x' not found (status code: 404)")` 의 `str()` 은 `"model 'x' not found (status code: 404) (status code: -1)"` 가 된다 (뒤에 `(status code: -1)` 이 붙는다). 그래서 수용 기준 #17 이 완전 일치가 아니라 `startswith("ollama error: ")` 접두사 비교인 것이다. 이 접미사를 없애려고 `llm.py` 를 고치지 마라.
2. **라이브 스모크(#26)는 정답값을 단언하지 않는다.** 클라우드 모델이라 온도 0이어도 출력이 보장되지 않는다. "SQL 이 나온다" 까지만 본다. 정확도 측정은 007 골든셋의 일이다.
3. **[이번 범위 밖] 프롬프트 개선을 하지 마라.** `SYSTEM_PROMPT` 는 스파이크 18/18 로 검증된 상태이고, 지금 문구를 바꾸면 개선인지 악화인지 잴 방법이 없다. few-shot 예시 추가를 포함해 모든 프롬프트 변경은 007 이후다.
