## 목표

`ensure_safe_sql()` 을 통과한 SQL 만 Sakila 에 실행해 결과를 돌려주는 `run_query()`, 그리고 LLM 프롬프트에 넣을 스키마를 읽어오는 `fetch_schema()` 를 만든다.
이 스펙이 끝나면 "SQL 문자열 → 실제 행" 과 "DB → 스키마 목록" 두 경로가 완성되고, 남는 것은 "질문 → SQL" 뿐이다.

## 설계 결정 (이미 정해졌다. 바꾸지 마라)

1. **`db.py` 는 접속 정보를 스스로 읽지 않는다.** 모든 공개 함수가 `settings: Settings` 를 인자로 받는다. `load_settings()` 를 `db.py` 안에서 호출하지 마라 — 그러면 테스트가 실제 `.env` 에 묶여 버린다.

2. **SQL 이 들어오는 경로는 두 개이고, guard 는 그중 하나에만 붙는다.** 이 스펙에서 가장 중요한 부분이다.

   | 함수 | SQL 출처 | `ensure_safe_sql` |
   |---|---|---|
   | `run_query(sql, ...)` | **바깥에서 받는다** (나중에 LLM 이 생성) | **반드시 호출한다** |
   | `fetch_schema(settings)` | 모듈 상수 `SCHEMA_SQL` 하나뿐 | 호출하지 않는다 |

   `SCHEMA_SQL` 은 `information_schema` 를 읽으므로 `ensure_safe_sql` 에 넣으면 `system schema access is not allowed: information_schema` 로 거부당한다. **이때 guard 를 고치지 마라.** guard 는 "안전한 SQL 판별기"가 아니라 "믿을 수 없는 출처의 SQL 필터"다. `SCHEMA_SQL` 은 우리가 소스에 박아 넣은 신뢰된 문장이라 애초에 필터 대상이 아니다.

   대신 구조로 보장한다: **`fetch_schema` 에 `sql` 파라미터를 만들지 마라.** 실행할 문장이 상수 하나뿐이면 위험한 SQL 이 흘러들어올 통로 자체가 없다. 마찬가지로 `run_query` 에 `skip_guard` / `unsafe` / `bypass` 같은 인자를 만들지 마라.

3. **커넥션은 매 호출마다 열고 닫는다.** 커넥션 풀·전역 캐시·싱글턴·`@lru_cache` 를 만들지 마라. Sakila 는 로컬 컨테이너이고 조기 최적화할 이유가 없다.

4. **쓰기를 하지 않으므로 `commit()` 을 호출하지 않는다.** `autocommit` 을 건드리지 마라.

5. **`max_rows` 는 이중 방어다.** guard 가 `LIMIT` 을 붙여주지만, LLM 이 `LIMIT 100000` 을 직접 써 넣으면 guard 는 그대로 둔다(002 설계결정 4). 그래서 `run_query` 는 `cursor.fetchmany(max_rows)` 로 **가져오는 행 수도 다시 제한한다.**

6. **결과는 불변 자료구조로 돌려준다.** `list` 가 아니라 `tuple`, dataclass 는 `frozen=True`. 반환값을 나중에 그래프 상태에 넣을 것이므로 변형 가능하면 곤란하다.

7. **`fetch_schema` 는 뷰도 포함한다.** Sakila 에는 BASE TABLE 16개, VIEW 7개가 있다. 어느 쪽을 프롬프트에 넣을지는 004 `schema.py` 가 판단하므로, 이 계층은 `table_type` 을 붙여서 **전부** 돌려준다. 여기서 필터링하지 마라.

8. **DB 에러는 `QueryError` 로 감싼다.** `pymysql` 예외 타입이 호출자에게 새어 나가면 나중에 `graph.py` 가 `pymysql` 을 import 해야 한다. 단, `UnsafeSQLError` 는 감싸지 않고 그대로 올려보낸다 — 호출자가 "SQL 이 위험함"과 "DB 가 거부함"을 구분해야 하기 때문이다.

## 파일별 계약

### `t2s/db.py`

```python
from dataclasses import dataclass

import pymysql
import pymysql.err

from t2s.config import Settings
from t2s.guard import MAX_ROWS, ensure_safe_sql


class QueryError(RuntimeError):
    ...


@dataclass(frozen=True)
class QueryResult:
    columns: tuple[str, ...]
    rows: tuple[tuple, ...]
    sql: str


@dataclass(frozen=True)
class ColumnInfo:
    table_name: str
    table_type: str
    column_name: str
    data_type: str
    is_nullable: bool
    column_key: str


SCHEMA_SQL: str = (
    "SELECT c.TABLE_NAME, t.TABLE_TYPE, c.COLUMN_NAME, "
    "c.DATA_TYPE, c.IS_NULLABLE, c.COLUMN_KEY "
    "FROM information_schema.COLUMNS AS c "
    "JOIN information_schema.TABLES AS t "
    "ON t.TABLE_SCHEMA = c.TABLE_SCHEMA AND t.TABLE_NAME = c.TABLE_NAME "
    "WHERE c.TABLE_SCHEMA = %s "
    "ORDER BY c.TABLE_NAME, c.ORDINAL_POSITION"
)


def connect(settings: Settings) -> pymysql.connections.Connection:
    ...


def run_query(sql: str, settings: Settings, max_rows: int = MAX_ROWS) -> QueryResult:
    ...


def fetch_schema(settings: Settings) -> tuple[ColumnInfo, ...]:
    ...
```

`SCHEMA_SQL` 은 위 문자열을 **글자 그대로** 쓴다. 스키마 이름은 반드시 `%s` 파라미터 바인딩으로 넘긴다. f-string·`%`·`.format()`·`+` 로 SQL 을 조립하지 마라.

---

#### `connect(settings: Settings) -> pymysql.connections.Connection`

동작 규칙 (번호대로, 순서대로):

1. `pymysql.connect()` 를 아래 인자로 호출한다. 인자를 빼거나 더하지 마라.
   - `host=settings.db_host`
   - `port=settings.db_port`
   - `user=settings.db_user`
   - `password=settings.db_password`
   - `database=settings.db_name`
   - `charset="utf8mb4"`
   - `connect_timeout=3`
2. `pymysql.err.OperationalError` 가 발생하면 `QueryError(f"cannot connect to {settings.db_host}:{settings.db_port}: {exc.args[1]}")` 를 던진다. `raise ... from exc` 를 사용한다.
3. 성공하면 커넥션 객체를 그대로 반환한다. **이 함수는 커넥션을 닫지 않는다.** 닫는 책임은 호출자에게 있다.
4. 로깅·print 를 하지 마라.

발생 예외:
| 예외 | 조건 | 메시지 형식 |
|---|---|---|
| `QueryError` | 접속 실패 (`OperationalError`) | `cannot connect to 127.0.0.1:3310: Can't connect to MySQL server on '127.0.0.1'` |

---

#### `run_query(sql: str, settings: Settings, max_rows: int = MAX_ROWS) -> QueryResult`

동작 규칙 (번호대로, 순서대로):

1. `safe_sql = ensure_safe_sql(sql, max_rows=max_rows)` 를 호출한다. 여기서 나온 `UnsafeSQLError`·`ValueError`·`TypeError` 는 **잡지 말고 그대로 올려보낸다.** `try/except` 로 감싸지 마라 (설계결정 8).
2. `connection = connect(settings)` 로 접속한다. 여기서 나온 `QueryError` 도 그대로 올라간다.
3. `try/finally` 를 쓴다. `finally` 에서 `connection.close()` 를 호출한다. 4~7번에서 어떤 예외가 나든 커넥션은 반드시 닫힌다.
4. `with connection.cursor() as cursor:` 안에서 `cursor.execute(safe_sql)` 를 호출한다. `execute` 에 파라미터를 넘기지 마라 — `safe_sql` 은 이미 완성된 문장이다.
5. `cursor.execute` 에서 `pymysql.err.OperationalError`, `pymysql.err.ProgrammingError`, `pymysql.err.InternalError`, `pymysql.err.DataError` 중 하나가 발생하면 `QueryError(f"query failed [{exc.args[0]}]: {exc.args[1]}")` 를 던진다. `raise ... from exc` 를 사용한다. 이 4개 클래스만 잡는다 — `except Exception` 을 쓰지 마라.
6. `columns` 는 `tuple(d[0] for d in cursor.description)` 으로 만든다. `cursor.description` 이 `None` 이면 빈 튜플 `()` 로 둔다.
7. `rows` 는 `tuple(cursor.fetchmany(max_rows))` 로 만든다. `fetchall()` 을 쓰지 마라 (설계결정 5). 남은 행은 버린다.
8. `QueryResult(columns=columns, rows=rows, sql=safe_sql)` 를 반환한다. `sql` 필드에는 **원본 `sql` 이 아니라 `ensure_safe_sql` 이 돌려준 정규화된 문자열**을 넣는다.
9. 로깅·print 를 하지 마라.

발생 예외:
| 예외 | 조건 | 메시지 형식 |
|---|---|---|
| `UnsafeSQLError` | guard 가 거부 (감싸지 않고 통과) | `only SELECT is allowed, got: DROP` |
| `QueryError` | 접속 실패 | `connect()` 표와 동일 |
| `QueryError` | 실행 실패 | `query failed [1146]: Table 'sakila.nope' doesn't exist` |

---

#### `fetch_schema(settings: Settings) -> tuple[ColumnInfo, ...]`

동작 규칙 (번호대로, 순서대로):

1. **`sql` 파라미터를 만들지 마라.** 이 함수가 실행하는 문장은 `SCHEMA_SQL` 하나뿐이다 (설계결정 2).
2. `ensure_safe_sql` 을 호출하지 마라. `SCHEMA_SQL` 은 guard 대상이 아니다.
3. `connection = connect(settings)` → `try/finally` 로 `close()`. `run_query` 3번과 동일하다.
4. `cursor.execute(SCHEMA_SQL, (settings.db_name,))` — 스키마 이름은 반드시 파라미터로 바인딩한다.
5. 5번 예외 처리는 `run_query` 5번과 동일하다 (`QueryError(f"query failed [{errno}]: {msg}")`).
6. 각 행 `(table_name, table_type, column_name, data_type, is_nullable, column_key)` 를 `ColumnInfo` 로 변환한다. 변환 규칙:
   - `is_nullable` — DB 가 문자열 `"YES"` / `"NO"` 를 준다. `value == "YES"` 로 `bool` 을 만든다.
   - 나머지 5개는 문자열 그대로 담는다. 대소문자를 바꾸지 마라 (`table_type` 은 `"BASE TABLE"` / `"VIEW"`, `data_type` 은 소문자 `"int"` / `"varchar"` / `"enum"` 으로 온다).
7. 결과를 `tuple` 로 반환한다. 정렬은 `SCHEMA_SQL` 의 `ORDER BY` 가 이미 보장하므로 파이썬에서 다시 정렬하지 마라.
8. 행 수를 제한하지 마라. `fetchall()` 을 쓴다 (여기서는 `fetchmany` 가 아니다 — 스키마는 전량이 필요하다).
9. 로깅·print 를 하지 마라.

발생 예외:
| 예외 | 조건 | 메시지 형식 |
|---|---|---|
| `QueryError` | 접속 실패 | `connect()` 표와 동일 |
| `QueryError` | 실행 실패 | `query failed [1142]: SELECT command denied to user ...` |

## 수용 기준

구현 세션은 아래 표를 그대로 테스트 코드로 옮긴다. 기대값은 전부 라이브 `t2s-sakila` 컨테이너(MySQL 8.4.11, Sakila 표준 덤프)에서 실측한 값이다.

| # | 입력 | 기대 출력 | 비고 |
|---|---|---|---|
| 1 | `run_query("SELECT COUNT(*) FROM film", settings)` | `.columns == ("COUNT(*)",)`, `.rows == ((1000,),)`, `.sql == "SELECT COUNT(*) FROM film LIMIT 200"` | 세 필드 전부 단언. `sql` 은 guard 가 LIMIT 을 붙인 결과 |

| 3 | `run_query("SELECT title FROM film ORDER BY title LIMIT 3", settings)` | `.rows == (("ACADEMY DINOSAUR",), ("ACE GOLDFINGER",), ("ADAPTATION HOLES",))`, `.sql == "SELECT title FROM film ORDER BY title LIMIT 3"` | 기존 LIMIT 보존(guard 설계결정 4) |
| 4 | `run_query("SELECT * FROM film LIMIT 1000", settings)` | `len(result.rows) == 200` | 이중 방어. LIMIT 1000 인데도 `fetchmany(200)` 이 막는다 (설계결정 5) |

| 7 | `run_query("DROP TABLE film", settings)` | `UnsafeSQLError`, `str(exc.value) == "only SELECT is allowed, got: DROP"` | guard 예외가 감싸이지 않고 그대로 올라옴 (설계결정 8). `QueryError` 가 아님을 `type()` 으로도 단언 |

| 9 | `run_query("SELECT 1; DROP TABLE film", settings)` | `UnsafeSQLError`, `str(exc.value) == "multiple statements are not allowed"` | |
| 10 | `run_query("SELECT * FROM nope", settings)` | `QueryError`, `str(exc.value).startswith("query failed [1146]: ")` | 없는 테이블. 접두사 비교 |
| 11 | `run_query("SELECT FROM", settings)` | `QueryError`, `str(exc.value).startswith("query failed [1064]: ")` | 문법 오류. guard 는 통과함(첫 토큰이 SELECT)에 주의 |
| 12 | `connect(Settings(...))` 에 `db_port=1` 을 넣어 호출 | `QueryError`, `str(exc.value).startswith("cannot connect to 127.0.0.1:1: ")` | 접속 실패. `Settings` 를 직접 만들어 넘긴다 (`.env` 를 건드리지 않는다) |
| 13 | `len(fetch_schema(settings))` | `131` | Sakila 전체 컬럼 수 (실측) |
| 14 | `len({c.table_name for c in fetch_schema(settings)})` | `23` | 테이블 23개 |
| 15 | `len({c.table_name for c in fetch_schema(settings) if c.table_type == "BASE TABLE"})` / `... == "VIEW"` | `16` / `7` | 뷰도 포함됨 (설계결정 7). 두 단언 모두 작성 |
| 16 | `fetch_schema(settings)[0]` | `ColumnInfo(table_name="actor", table_type="BASE TABLE", column_name="actor_id", data_type="int", is_nullable=False, column_key="PRI")` | `ORDER BY` 로 첫 행이 결정됨. dataclass 전체를 `==` 비교 |
| 17 | `fetch_schema(settings)` 중 `table_name=="film" and column_name=="rating"` 인 것 | `data_type == "enum"`, `is_nullable is True`, `column_key == ""` | `"YES"` → `True` 변환, 빈 `column_key` 경계값 |
| 18 | `fetch_schema(settings)` 중 `table_name=="film" and column_name=="title"` 인 것 | `data_type == "varchar"`, `is_nullable is False`, `column_key == "MUL"` | `"NO"` → `False` 변환 |
| 19 | `len([c for c in fetch_schema(settings) if c.table_name == "film"])` | `13` | |
| 20 | `fetch_schema` 의 반환값 타입 | `isinstance(result, tuple)` 이고 모든 원소가 `ColumnInfo` | `list` 가 아님 (설계결정 6) |
| 21 | `connect(settings)` 로 얻은 커넥션을 `close()` 한 뒤 `connection.open` | `False` | `connect` 가 커넥션을 닫지 않고 반환하는지 + 호출자가 닫을 수 있는지 확인 (계약 3번) |
| 22 | `inspect.signature(fetch_schema).parameters` 의 키 목록 | `["settings"]` | **`sql` 파라미터가 없음을 코드로 단언한다** (설계결정 2). `inspect` 를 import 해서 확인 |

## 검증 명령

PowerShell 에서 저장소 루트에 서서 한 줄씩 실행한다. (`&&` 금지.)

컨테이너 기동 확인:
```powershell
docker compose -f docker/docker-compose.yml up -d
```

새 테스트:
```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_db.py -v
```
기대 출력: `failed 0`, `error 0`, **`skipped 0`**. skip 이 하나라도 있으면 통과가 아니다 (테스트 규칙 3).

전체 회귀:
```powershell
.\.venv\Scripts\python.exe -m pytest tests/ -q
```
기대 출력: `50 passed` 보다 큰 수. 001 의 12개와 002 의 38개가 전부 그대로 통과해야 한다. `failed`/`error`/`skipped` 는 0.

**guard 무변경 확인 (가장 중요):**
```powershell
git diff --stat t2s/guard.py t2s/config.py
```
기대 출력: **빈 출력.** 한 줄이라도 나오면 범위 이탈이고 FAIL 이다.

guard 가 여전히 `information_schema` 를 막는지 직접 확인:

```powershell
.\.venv\Scripts\python.exe -c "from t2s.guard import ensure_safe_sql as f; f('SELECT * FROM information_schema.TABLES')"
```
기대 출력: 마지막 줄이
```

```

```powershell
.\.venv\Scripts\python.exe -c "import ast; t=ast.parse(open('t2s/db.py',encoding='utf-8').read()); print(sorted({n.module or '' for n in ast.walk(t) if isinstance(n,ast.ImportFrom)} | {a.name for n in ast.walk(t) if isinstance(n,ast.Import) for a in n.names}))"
```

## 하지 말 것

- **`t2s/guard.py` 를 수정하지 마라.** `information_schema` 에 막힌다고 `SYSTEM_SCHEMAS` 를 손대는 것이 이 스펙에서 가장 하기 쉬운 실수이자 가장 심각한 위반이다.
- `run_query` 에 `bypass` / `skip_guard` / `unsafe` / `raw` 같은 guard 우회 인자를 만들지 마라.
- `fetch_schema` 에 `sql` 파라미터를 만들지 마라. `SCHEMA_SQL` 을 인자 기본값으로 노출하지도 마라.
- SQL 을 f-string·`%`·`.format()`·문자열 덧셈으로 조립하지 마라. 스키마 이름은 `%s` 바인딩이다.
- `db.py` 안에서 `load_settings()` 나 `os.environ` 을 호출하지 마라.
- 커넥션 풀·전역 커넥션·`@lru_cache` 를 만들지 마라.
- `fetchall()` 로 결과를 전부 가져오지 마라 (`run_query` 한정. `fetch_schema` 는 `fetchall` 이 맞다).
- `except Exception:` 을 쓰지 마라. 계약에 적힌 pymysql 예외 4종만 잡는다.
- 실행 타임아웃을 파이썬에서 구현하지 마라. 서버의 `max_execution_time=10000` 이 담당한다.
- 결과를 `list` 나 `dict` 로 돌려주지 마라. `tuple` + frozen dataclass 다.
- 테스트에서 DB 미기동을 이유로 `pytest.skip` 하지 마라.
- `t2s/schema.py`, `t2s/llm.py`, `t2s/graph.py`, `t2s/cli.py` 를 만들지 마라. 다음 스펙이다.
- 커밋하지 마라.

## 질문

구현 세션이 막혔을 때 여기에 적는다. 아래는 **스펙 작성 시점에 확인된 사항**이다.

1. **실행 타임아웃은 예외를 던지지 않는다.** `SELECT SLEEP(15)` 를 실측한 결과, 서버의 `max_execution_time=10000` 이 10초 후 쿼리를 중단시키지만 에러가 아니라 **정상 결과 `(1,)` 을 돌려준다.** 즉 "느린 쿼리가 잘렸는지"를 호출자가 알 방법이 이 계층에는 없다. 이번 스펙의 범위 밖이므로 수용 기준에 넣지 않았다. 나중에 쿼리 효율성(v2)을 다룰 때 처리한다.
2. **`docs/WORKFLOW.md` 의 MySQL 버전 표기가 8.4.10 이지만 실제 컨테이너는 8.4.11 이다.** 문서 갱신은 사람이 커밋 단계에서 판단한다. 이 스펙에서 `docs/` 를 고치지 마라.
